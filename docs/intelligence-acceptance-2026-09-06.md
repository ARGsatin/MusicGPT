## 结论

五阶段升级已通过代码、固定轨迹、真实模型、公开 API 和浏览器可见界面的联合验收。当前继续运行在 `shadow`，不会因为本次验收绕过 7 天、50 个有效推荐决策及安全护栏直接切换 `adaptive`。

## 自动化门槛

- 固定离线轨迹：150/150 通过；文字和语音共执行 300 次，另有 12 次本地回退规划器通道执行。
- 真实模型高风险门槛：评测器 `isolated-music-command-v6`，语料哈希 `1cb3be907c737fb52307b76a697180dbdfea6557290e78a4b65e1bb4f3fe6750`；25 条中 24 条通过，成功率 96%，错误动作率 0，文字/语音通道差异 0，`releaseReady=true`。
- 唯一未命中样例 `ctx-021`（“别动已经听过的歌，只调整后面”）返回了无副作用的澄清，而固定期望是直接答复；它不改变当前歌曲、队列或画像，因此不属于错误动作。
- 常规工程门槛：`npm test` 共 400 项通过（shared 14、server 305、web 81）；`npm run typecheck`、`npm run build`、`git diff --check` 均通过。

真实模型缓存只保存样例 ID 和脱敏判定。25 表示固定规划任务数；模型供应商返回无效 JSON 时，兼容层可能对单个任务进行有限重试，因此它不是严格的计费请求上限。

## 本机公开接口验收

- `/health` 确认 checkout 为 `main`、运行根目录为 `D:\MusicGPT\apps\server`；API、Web 和 NCM 三项健康。
- 明确 `trackKey` 文字点歌后，`/api/chat/stream` 最终 `result.response.now.track.trackKey` 与请求完全一致，命令结果为 `executed`。
- 普通开放聊天在最终结果前收到 57 个真实 `text_delta`；首个增量约 574 ms，最终结果约 1392 ms，当前歌曲保持不变。
- 网易云与 QQ 曲源均处于连接状态；两者都提供搜索和播放能力。
- 当日日计划为三时段各 10 首，晨间探索位 4 首，午后和晚间计划可见跨曲源候选；已消费曲目记录保留。

## 浏览器可见验收

- 播放器显示真实当前曲目、曲源、播放控制和五个快捷纠正入口。
- “为什么放这首”可展开，并显示实际参与决策的“文字点歌”证据。
- “今日计划”显示晨间探索、午后柔和、晚间回忆三段及双曲源状态。
- “音乐画像”与对话记忆分离，按显式、达到阈值的隐式、旧数据基线分组，并提供确认、降低、屏蔽、删除和自动信号重置控件；`taste.md` 规则标记为只读。
- 浏览器控制台未发现 error 级日志。

## 运行策略与边界

- 当前策略：`shadow`，版本 `listening-policy-v1`，影子样本数 12；状态中心保留回退原因 `playback_error_rate`。
- 本次没有强制切换 `adaptive`，因为持续时间和样本量门槛仍应由运行数据自然满足。
- 真实模型验收复用了文字/语音统一命令通道，但没有代替真人对麦克风、浏览器权限和 Qwen WebRTC 音频链路的人工听感测试。
- 验收烟测会留下必要的本地播放事实和两条聊天记录；未写入凭证、Cookie、原始音频或模型原文。
- 未推送远端、未部署生产。健康接口中的 release 是当前 `main` 基准提交；本次升级仍位于含既有用户改动的工作树中。
